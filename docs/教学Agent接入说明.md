# 本地教学 Agent

首页《茉莉花》备课已连接真实模型适配层；必须登录。其他两首仍为模板演示。程序不会以模板冒充模型成功。未配置时可浏览现有课程，但新的 Agent 请求会明确失败。

## 服务端配置

在启动 Node 的进程环境中设置：

- `TEACHING_API_KEY`：模型服务密钥。不要填入页面、源码或提交到仓库。
- `TEACHING_MODEL`：你的模型服务中支持严格 JSON Schema 输出的模型 ID。
- `TEACHING_BASE_URL`：可选，默认 `https://api.openai.com/v1`；兼容服务填写其 `/v1` 根地址。本地服务允许回环 HTTP，远程必须 HTTPS。
- `TEACHING_PROTOCOL`：可选，默认 `json_schema`（OpenAI 结构化输出协议）。设为 `json_object` 时适配 DeepSeek 等仅支持 JSON Output 的服务：schema 写入提示词，返回仍由本地校验器逐字段强制检查，不满足即失败——不是无校验文本。

配置完成后，在项目目录运行 `node server.cjs`，打开 http://127.0.0.1:4173。现有服务需先停止，再从已设置环境变量的终端启动。程序不自动读取 `.env`。不要在聊天里提供密钥。

适配器使用 Chat Completions 的 `response_format.json_schema`，`strict:true`。兼容服务也必须支持该协议；不支持时明确失败，不降级为无校验文本。接口依据：https://platform.openai.com/docs/guides/structured-outputs

需求文本和课程条件会发给所配置的模型服务，规划阶段还发送已校对的本地资料与（默认开启的）互联网检索到的公开网页摘录。账号密码、姓名、学校、学生个人记录和录音不作为模型输入。需求栏请填写课堂条件，不填写学生个人信息。不希望课堂需求相关关键词出网时，设置 `TEACHING_WEB_SEARCH=off`。

## 密钥轮换（怀疑泄露时 / 定期更换）

本项目的密钥只存在于**进程环境变量**，不进代码、不进仓库、不进 `.env`。所以轮换 = 在服务商后台换一把 + 改本机环境变量，两步。

**1）服务商后台（必须人工操作，无法代劳）**

以当前配置的 DeepSeek 为例：登录 https://platform.deepseek.com → 左侧 *API Keys* → 对旧密钥点 **删除/吊销** → **创建新的 API key** → **立刻复制保存**（DeepSeek 只在创建时显示一次完整密钥，关掉就再也看不到）。若是 OpenAI 则是 https://platform.openai.com/api-keys ，其它兼容服务同理。

顺序建议：**先创建新密钥并配置好 → 验证新密钥可用 → 再吊销旧的**，避免中间断档；但如果已确认泄露，则**先吊销**，宁可短暂不可用。

**2）改本机环境变量（Windows，用户级持久化）**

```powershell
setx TEACHING_API_KEY "<新密钥>"
```

`setx` 只影响**之后新开**的终端，当前已开的窗口仍是旧值。改完重开一个终端，或在本窗口补一句 `$env:TEACHING_API_KEY='<新密钥>'`。改完**必须重启服务**才会生效（服务启动时才读取）。

**3）验证（两条命令都不会显示密钥本身）**

```powershell
# 本地配置体检：只打印长度与首尾各 3 位
node scripts\check-key-config.cjs

# 服务商侧探活：确认新密钥可用 / 旧密钥已失效
$k=[Environment]::GetEnvironmentVariable('TEACHING_API_KEY','User')
(Invoke-RestMethod -Uri 'https://api.deepseek.com/user/balance' -Headers @{Authorization="Bearer $k"}).is_available
```

轮换后建议再确认一次：旧密钥若已吊销，用旧密钥请求会返回 401（`is_available` 为 false 或直接鉴权失败）。

**其他要注意的地方**

- 不要为了省事把密钥写进 `.env`、启动脚本或任何会被提交的文件；`.gitignore` 已排除 `.env`，但排除不等于安全，仓库历史里一旦出现就得重新轮换。
- 泄露发生在聊天记录里时，**聊天记录本身不会被轮换清掉**——轮换的作用是让那串字符立刻失效，这一步才是关键。
- 轮换后余额若出现异常消耗，说明旧密钥在泄露后已被他人使用，需联系服务商核查。

## 实际流程与记录

1. `model.parse`：模型将自由文本和默认条件解析为严格结构化需求。
2. `local.search`：以模型生成的查询对本地两条资料作关键词检索排序，返回谱源转录和项目教学规则。不是联网搜索，也不声称拥有完整教育知识库。
3. `web.search`：默认开启的互联网检索阶段。多引擎无密钥搜索：优先 Bing（国内网络可达，实测固定查询「茉莉花 江苏民歌」稳定命中何仿改编条目、腾讯视频、网易云等歌曲资料），DuckDuckGo 作海外备选；正文抓取被反爬拦截（403/超时）时自动降级用搜索摘要，每条资料仍带真实链接。全部 HTTPS、单次 8 秒超时、单页截 8000 字、带歌曲相关性排序，整理成一份带真实链接的 `web` 资料交给规划模型；活动的 `sourceIds` 可引用 `web`，来源 URL 全程记录在任务事件与资料列表里可追溯。检索失败（断网、引擎全部不可用）时如实记录 `WEB_SEARCH_UNAVAILABLE` 并只用本地资料继续——不编造来源，也不因此失败整个任务。单元测试通过注入假 fetcher 覆盖，不发真实请求。
4. `model.plan`：模型依据检索内容生成7个活动，附教师动作、学生动作、目标、观察证据、资料 ID 和允许的工具。
5. `plan.validate`：检查结构、引用 ID、可执行工具、分钟数之和。调、拍号、音符和音频仍由固定教学对象提供。

任务保存于忽略目录 `.local-data/agent-tasks/`，包含所有者、任务ID、模型名、需求、事件时间、工具、结果、决策摘要与错误代码。只保存允许的结构化输出，不保存原始模型响应、内部推理或请求头。账号只能通过接口读取自己的任务。重启后运行中的任务标记为中断，不冒充完成。首页“查看我的 Agent 任务”可恢复结果。

每账号同时1个任务，全局最多3个，单次模型请求60秒超时；网络、拒答、截断、结构不符、时长不符均失败并留记录。失败不覆盖上一份有效教案。修改条件会使已生成方案失效并回到模板，需重新请求 Agent。

课堂按钮按白名单执行标准参考、慢速参考、预备拍、节拍器或教师观察。不是任意代码执行器。真实音频测量已接入 Agent，见下一节。

## 声学诊断与班级汇总

真实录音的测量结果可以直接进入 Agent 编排，这两类任务不依赖模型配置，没有密钥也能跑通规则链路：

1. `POST /api/agent/coaching-tasks`（body：`{attemptId}`）→ 任务 `kind: coaching`
   - `analyze_singing`：读取这条录音已保存的测量（是否有效、平均绝对偏差、速度比、逐音数）
   - `diagnose`：按音分阈值、下行音、速度比与起音误差、长音时值、与历史对比判定问题类型，输出证据与 `basedOn: measurement`
   - `choose_training`：为判定出的问题选择一份含分钟数与步骤的训练策略
   - `generate_feedback`：生成教师话术与学生话术；已配置模型时会额外请求一次结构化文本，失败自动回退到规则文案（`feedbackSource` 为 `rules` 或 `model`）
2. `POST /api/agent/class-report-tasks` → 任务 `kind: class-report`，只用本账号已保存的有效录音汇总样本量、平均绝对偏差、平均速度比与被排除的无效录音数；样本量为 0 时明确说明，不生成任何推测数字。

诊断只依据音准、节奏与时值测量，不推断气息、心理状态或唱法原因；无效录音不产生诊断结论，也不进入班级统计。前端入口：「AI听唱」测量结果里的“生成诊断与训练建议”，以及课堂报告页的“班级汇总（Agent）”。

## 验证

`npm test`（含 `agent.test.cjs`、`coaching.test.cjs`、`lesson.test.cjs`、`auth.test.cjs`）

测试适配器使用明确的测试替身，不算真实模型联调。没有服务端密钥时无法验证服务商权限、模型可用性和真实教学质量；需配置后完成一次真实生成，并由教师审阅活动内容。结构校验不等同于教学质量认证。本次不部署、不发布。
