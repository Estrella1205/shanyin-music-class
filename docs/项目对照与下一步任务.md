# 声入山野｜项目方案对照与下一步任务

更新日期：2026-09-12。本文对照用户提供的比赛规则、完整教学 Agent 方案和本地实际代码。方案中的设想不等于已实现能力，也不作为真实研究证据。

## 1. 项目定位与比赛切入点

**为缺少专业音乐教师与乐器设备的乡村小学，提供可执行、会根据练习表现调整的音乐课堂。**

主要使用者是非音乐专业的任课教师与支教教师，儿童在教师组织下参与课堂。差异化不应只停留在山野视觉或聊天备课，应落在“教学条件约束下的规划”和“真实听唱结果驱动的练习调整”上。自然声音和乡土音乐作为教学入口，是第二条特色线。

目前没有教师访谈、试教结果或学生学习效果数据，因此“痛点普遍程度”“学习提升幅度”“学校付费意愿”均属于待验证假设。

## 2. 这轮改动

- 项目名称更改为“声入山野”。原样使用用户提供的完整 Logo，不重新生成或修改图案。
- 桌面基准为 1440 × 900；首页、备课、课堂、听唱、报告、班级和山野声音统一山野视觉与布局密度。内容较长时允许滚动，不裁掉功能；小屏采用响应式排布。
- AI备课采用课堂条件、六步规划状态、工作记录三栏；日志对应本地规则真实执行的任务，明确不是大模型思维或 RAG 检索。
- 增加本地注册、登录、个人称呼/学校/头像修改、修改密码、切换账号与退出。
- 本地服务使用 scrypt 加盐密码摘要、HttpOnly 会话 Cookie、登录限流和来源校验。账号数据在 `.local-data/`，不进入源码仓库；账号之间课堂数据隔离。

## 4. 下一步的明确顺序

### 任务一：先把“一节课”做成可验证的教学对象

**2026-09-12已完成技术交付。** 详见 `任务一验收-茉莉花.md`。固定学院公开谱例的开头两小节，源谱1=E、4/4拍；教学参考移调1=C，80/60 BPM。逐音数据、Schema、三份自制WAV、来源记录、目标与活动、设备和人数约束已落地并通过测试。真实教师试教审定不包含在本次技术验收内。下一步转入任务二；不再将该版本套用2/4拍。

以《茉莉花》为首个正式垂直案例，确定一个短乐句，校对参考音高、调、拍号、每个音的时值和参考音频。保留现有三首歌作为模板演示，但先集中验证一首。

交付物：`lesson schema`、参考乐句、教学目标、设备约束、分环节活动、来源/版权记录。验收：不同人数、时长和有无钢琴会产生合理改变，所有环节时间和等于总时长。

### 任务二：接入真正的教学 Agent

在本地后端增加模型适配层与结构化输出校验。流程为需求解析→教学资料检索→教案规划→输出可执行活动。保存任务、工具、结果和决策摘要，避免展示或编造“内部思维”。密钥只放服务端环境变量。

交付物：一条真实模型/工具调用链；缺失条件、超时和不支持内容的回退路径。验收：同一课堂请求能稳定生成符合约束的计划，日志与实际操作一致。模型供应商及费用待用户选择后确定，不假定现有付费账号。

### 任务三：实现真实音频分析（核心技术优先）

从安静环境的一位演唱者、短乐句开始。先检测录音质量，再做基频提取、音符转换与对齐。节奏单独验证；不要把全班混唱直接当作单个学生的准确评分。

交付物：偏差位置、偏差方向、可信度与无效输入说明。验收：标准合成音、已知偏低音、节奏偏快、静音与噪声样本均产生预期结果。声学偏差不能直接推断气息、心理或唱法原因。

### 任务四：让检测结果真正决定下一步

策略规则读取真实测量值，决定慢速模唱、阶梯音、节拍练习或要求重新录音。复测必须使用第二次录音重新分析；没有进步也要如实呈现。

交付物：检测→决策→练习→复测→比较的闭环。验收：输入不同问题会选择不同训练；复测结果不固定升高；两次音频和指标可追溯。

### 任务五：小范围试教和比赛材料

与目标教师验证备课时长、操作负担、设备条件与课堂可执行性，记录具体反馈及局限。把真实功能录成≤5分钟演示，再制作≤20页方案PDF。商业模式先验证学校/公益项目/教师培训的采购或服务需求，不编造客户与收入。

## 5. 建议的比赛展示链

1. 0:00–0:30：真实场景和目标教师，明确“无钢琴、非专业教师”的约束。
2. 0:30–1:30：一句话输入需求，展示真实规划与工具记录。
3. 1:30–2:15：开始课堂，示范一个短乐句。
4. 2:15–3:30：录音分析、问题定位、策略选择与练习。
5. 3:30–4:20：第二次录音复测，对比真实结果。
6. 4:20–5:00：课堂报告、推广条件与已知限制。

## 6. 上线前的完成标准

- 核心链路不依赖预设评分，能处理失败输入与网络错误。
- 教学资料和音源有明确来源及使用权；真实学生数据有授权和保护方案。
- 账号、录音、课堂记录按用户隔离；部署环境完成专门的安全检查。
- 1440 × 900 的主流程及小屏交互验收通过。
- PDF ≤20页，MP4 ≤5分钟，程序与资料表述一致。
- 用户明确审核同意后才上线；此前仅交付本地预览和源代码。
