对照代码版本：`shanyin-demo` 当前工作区（26 项测试通过的状态）
编制日期：2026-09-13

## 0. 先看结论

你提的三件事，成熟度和风险差别很大，不能用同一种承诺方式做：

| 需求 | 性质 | 现实结论 |
|---|---|---|
| 权威来源 + 歌词 | 纯工程问题 | **可做，且必须先做**。它是另外两件事的地基 |
| 歌谱导入 → 课程安排 | 工程 + 识别问题 | **可做，但要分四条通道分级做**，主攻文本谱，不承诺图片全自动 |
| 音乐家生平 → 课件/视频 | 素材版权 + 模型幻觉问题 | **课件可靠，视频必须降级承诺**，严禁"模型直出生平" |

而且有一个共同的前提障碍，现在必须先拆掉：**当前数据模型只装得下一个硬编码乐句**，多一首歌都进不来，歌词更是无处安放。

## 1. 现状核查（基于真实代码，不是估计）

| 事项 | 现状 | 证据 |
|---|---|---|
| 歌词 | **全仓库 0 处**「歌词」字段 | `events[]` 只有 `midi / durationBeats / degree / slur` |

| 来源登记 | 只有 1 条谱源，无许可分级 | `molihua.lesson.json` → `source{title,url,pdfPage,rights}` |

## 2. 总体设计：把「素材」和「课程」拆成三层

```
L0 来源层  knowledge/sources/*.json      只放能证明出处的元数据 + 许可
        ↓  （版权闸门）
L1 乐谱层  knowledge/scores/*.score.json 音高 / 时值 / 小节 / 拍号调号 / 歌词
        ↓  （难度分析，客观计算）
L2 课程层  public/lessons/*.lesson.json  教学目标 / 活动 / 时长 / 设备约束（现有结构）
        ↓
        课件层  courses/*.slides.json     幻灯片 / 分镜脚本 / 视频
```

### 2.1 版权闸门（一等公民，不是事后补的合规）

```js
// server/licensing.cjs
// 只允许 redistribute:true 的内容进入 L1/L2 正文；否则降级为 link-only 引用
gate(source) → 'full' | 'quote' | 'link-only'
```

| 许可类型 | 允许入库正文 | 允许修改 | 说明 |
|---|---|---|---|
| `public-domain` | 是 | 是 | 作者终生 + 死后 50 年届满（至第 50 年 12 月 31 日） |
| `cc0` | 是 | 是 | 权利已放弃，无需署名 |
| `cc-by` / `cc-by-sa` | 是 | 是（SA 需同许可） | 必须署名 + 记录许可链接 |
| `institution-permission` | 是 | 按授权范围 | 需记录授权凭证编号与日期 |
| `excerpt-only` | **否**（仅可引用 ≤2 小节） | 否 | 公开谱例仅查阅、原文件不分发时的默认档；《茉莉花》现属此档 |
| `link-only` | **否** | 否 | 只存 `url + title + 抓取时间 + sha256` |
| `unknown` | **否** | 否 | 一律按 link-only 处理 |

> 实现说明（`server/licensing.cjs`）：**「公有领域」不由来源自称，而由作者逝世年份推导。**
> 来源文件只能声明事实（谁、何时逝世），不能声明结论（它已公有）。闸门逐位计算「词」「曲」的保护期，
> 任何一位未届满即整体降级为 link-only。`excerpt-only` 是实施时新增的第六档，用于覆盖
> 「公开谱例未标许可、但我们只转录了有限短句」这一既有事实（《茉莉花》就是这种情况）。

三条硬规则：
1. **默认从严**：无法确认时按 `unknown` 处理，不进正文。
2. **中国民歌歌词属"民间文学艺术作品"**（《著作权法》第 6 条另有规定），权属规则与普通词曲不同 → 默认 link-only，除非有明确授权文件。
3. **上世纪创作的儿童歌曲**（如《小雨沙沙》这类）多数仍在保护期内 → 默认按在保护期处理，**不得**收录词曲正文。这条要先写进 `docs/`，避免后面误操作。

> 本方案给出的是技术闸门与工程纪律，不构成法律意见。上线前需要一次真实的权利核查。

## 3. 需求一：权威音乐来源 + 歌词

### 3.1 来源登记格式（新增 `knowledge/sources/`）

```json
{
  "id": "src-molihua-arthn-2021",
  "kind": "score",
  "title": "湖南艺术职业学院2021级公共文化服务与管理专业技能考核标准及题库",
  "creator": null,
  "url": "https://jwc.arthn.com/__local/...pdf",
  "retrievedAt": "2026-09-12",
  "sha256": "…",
  "license": {
    "type": "link-only",
    "url": null,
    "note": "公开谱例仅查阅；未标明开放许可"
  },
  "permittedUse": { "redistribute": false, "modify": false, "commercial": false },
  "verifiedBy": "人工核对原PDF第30页（印刷页27）",
  "verifiedAt": "2026-09-12"
}
```

要点：`sha256` 让"我引用的是哪一版"可追溯；`verifiedBy/verifiedAt` 让"谁校对过"可追溯——这正是评审最想看到的东西。

### 3.2 歌词进入 lesson Schema

**最小改动方案**：歌词直接挂在 `events[]` 上，音频生成与时间轴对齐逻辑完全不用改。

```json
{"id":"n01","measure":1,"beat":0,"midi":64,"pitch":"E4","durationBeats":1,
 "lyric":{"lineId":"l1","index":0,"syllable":"好","melisma":false}}
```

```json
"lyrics": {
  "language": "zh-Hans",
  "sourceId": "src-molihua-lyrics-xxx",
  "lines": [
    {"id":"l1","text":"好一朵美丽的茉莉花","syllables":["好","一","朵","美","丽","的","茉","莉","花"]}
  ]
}
```

`melisma` 字段用于中国民歌极常见的**一字多音**（一个字拖多个音符）；反向的**多字一音**用同一 `eventId` 绑定多个音节表达。

### 3.3 歌词必须过的校验（写进校验器）

1. 每个 `lineId` 的音节按 `index` 排序后能拼回原文（防错位）。
2. 非 `melisma` 的音符数量 = 音节数量（防漏字）。
3. 每行音节所属音符在同一乐句内，不跨行。
4. `lyrics.sourceId` 必须能解析到 `sources/` 里的记录，且 `permittedUse.redistribute === true`——**否则整个 lesson 拒绝生成**。

### 3.4 UI：三色徽章统一标注

延续项目已有的"演示 / 真实测量"诚实标注传统，把内容也分级：

| 徽章 | 含义 |
|---|---|
| 绿 · 已校对来源 | 有 `sources/` 记录 + `verifiedBy` + 许可允许 |
| 黄 · 教师导入待校对 | 老师自己导入的谱，尚未人工校对 |
| 灰 · 模型生成 | 模型产出的教学文案，必须标注 |

每首歌详情页可点开「来源卡」：原始链接（新窗口）、抓取时间、许可、校对人与日期、谱源哈希。

## 4. 需求二：教师导入歌谱 → 自动生成课程安排

### 4.1 四条导入通道，按可靠性排序

| 通道 | 可靠性 | 拿到什么 | 分期 |
|---|---|---|---|
| **山野简谱文本**（自研） | 极高 | 音高、时值、小节、歌词（逐字对齐） | **一期主攻** |
| **MusicXML / MIDI** | 极高 | 音高、时值、小节、调拍、**`<lyric>` 自带歌词** | 一期 |
| 手工谱面编辑器 | 高 | 同上（用户自己点） | 二期 |
| 图片 / PDF 歌谱 OMR | 中低，必须人工校对 | 需要逐音确认 | 三期，作为辅助通道 |

**不建议**把图片 OCR 作为主路径。简谱 OMR 准确率不稳，一旦识别错音，后面的难度分析和课程安排全错，老师会觉得"这玩意儿不靠谱"。文本谱可读、可手抄、可逐字检查，才是乡村教师的真实工作方式。

### 4.2 推荐主路径：山野简谱文本格式

面向中国乡村教师习惯的简谱：**两行对齐**——第一行音符，第二行歌词。看一眼就会用：

```
# 小练习 / 练习 / 4/4 / 1=C / 中速
# 来源: src-test-fixture

5 6 5 0 | 3 2 1 - |
啊 - - - | 呀 啦 啦 -
```

| 记号 | 含义 |
|---|---|
| `0`–`7` | 音级（`1=C` 时为 do–si）；`0` 是休止（占时值、不发声） |
| `'` / `,` | 高八度 / 低八度，可叠加（`1''`、`1,,`） |
| `-` | 音符行里 = 延长一拍；歌词行里 = 延续上一个字（一字多音） |
| `_` | 减半时值，可叠加（`_5` = 半拍，`__5` = 四分之一拍） |
| `.` | 附点 = 时值 ×1.5，写在音级前（`.5` = 附点四分 = 1.5 拍；`._5` = 附点八分 = 0.75 拍） |
| `|` | 小节线（每小节拍数必须与头部拍号一致，否则报错并指出第几小节） |
| `#` / `b` 前缀 | 升 / 降（一个音前最多一个） |

**歌词对齐规则**（老师最容易踩的坑）：把音符行去掉 `|` 后数一数有多少个「位置」——每个音符、每个延长的 `-`、每个休止符 `0` 都各算一个位置；歌词行去掉 `|` 后必须正好是同样多个位置。休止符和延长的位置歌词要写 `-`。带歌词导入必须在头部声明 `# 来源: <sourceId>`，否则会被版权闸门拦下。

头部一行写全 `# 歌名 / 体裁 / 拍号 / 调号 / 速度`；可选再写 `# 原调: 1=E`（记录谱面原本的调）与 `# 速度: 80`（把「中速」这类词钉成具体 BPM）。

真实样本——《茉莉花》开头两小节。下面这段就是 `serializeJianpu()` 从 `molihua.lesson.json` 导出的结果，可原样再导入（对应 §4.6 的可逆导出）：

```
# 茉莉花 / 江苏民歌 / 4/4 / 1=C / 中速 亲切的
# 原调: 1=E
# 速度: 80

3   _3  _5  _6  _1' _1' _6  | 5   _5  _6  5   -
```

硬性限制（一期）：只支持单声部、单乐段；拍号仅 2/4、3/4、4/4；不表示调号与连音线（`slur` 往返会丢失，测试里显式记录了这条限制）。谱面原调与演唱调分开记：`events` 记在演唱调上，`source.tonicMidi` 记原调，两者之差即 `teaching.transposeSemitones`。

**为什么这条最值得投**：解析器是一个无外部依赖的纯函数模块；老师手抄一首儿歌 5 分钟，立刻能听到自己录的歌变成可上课的课程——这是**演示效果最强、失败率最低**的一条路。

### 4.3 MusicXML 通道（顺带解决歌词来源）

`<note>` → `midi / durationBeats / measure`，`<lyric><text>` → `syllable`，`<time>` / `<key>` → 拍号调号，`<sound tempo>` → BPM。一期即可打通，且**导入即带歌词**，与需求一完美衔接。

### 4.4 导入流水线（复用现有 Agent 事件日志机制）

沿用 `teaching-agent.cjs` 的 `event(stage, tool, status, result)` 写法，新增 `kind: 'import'` 任务：

```
1. import.parse        上传文件/粘贴文本 → 原始记号流
2. score.normalize     记号流 → events[] + lyrics{} + teaching 元数据
3. score.validate      小节时值合计、音节数=音符数、音域、变音支持
4. difficulty.analyze  客观难度指标（见 4.5）
5. model.plan          在真实乐谱数据约束下生成课程安排（复用现有 planSchema）
6. build.score         生成参考/慢速/预备拍 WAV（复用 build-lesson.cjs）
7. output              产出 lesson 对象 + 建议课时 + 难点清单
```

第 5 步的输入里必须带上第 4 步算出的真实数字，并在提示词里写死「不可改变已校对的音符、调、拍号」——现有 `modelAdapter` 的系统提示词已经有这条纪律，直接沿用。

### 4.5 难度分析：用真实乐谱数据，不让模型瞎猜

这是"自动生成课程安排"能不能信的关键。全部可计算：

| 指标 | 计算方式 | 教学含义 |
|---|---|---|
| 音域跨度 | `max(midi) - min(midi)` | 超过 12 半音需移调 |
| 最大跳进 | 相邻音 `|Δmidi|` 最大值 | 大跳处必须分句 |
| 同音重复 | 连续相同 `midi` 的次数 | 呼应已有"重复高音"观察点 |
| 半拍/附点密度 | `durationBeats < 1` 占比 | 决定是否先慢速 |
| 变化音 | 是否出现调外音 | 小学阶段建议整段移调规避 |
| 乐句长度 | 按 `|` 与呼吸点切分 | 决定"分句模唱"的切点 |
| 字数/音数比 | 音节数 ÷ 音符数 | `>1` 表示存在一字多音，需单独训练 |

输出：`{ phraseBreaks:[...], suggestedBpm, transposeSemitones, lessonCount, difficulty:'easy|medium|hard', hardSpots:[{beat, reason}] }`

`hardSpots` 直接映射到 `coaching.cjs` 已有的问题类型（`pitch_accuracy` / `descending_pitch` / `rhythm_unstable` / `long_note_short`）→ **课程安排与后续诊断用同一套词汇**，老师看到的"这首难在哪"和"孩子错在哪"能对上。

### 4.6 导入后的可逆导出（重要）

必须能导出：`MusicXML` / `山野简谱文本` / `lesson JSON` / `课件 PDF`。

理由不是技术洁癖：老师会担心"我录进去的歌拿不出来了"。可逆导出直接决定采纳意愿。

## 5. 需求三：音乐家生平 → 课件 / 教学视频

### 5.1 先讲风险，再讲方案

- **模型直出"生平"= 幻觉重灾区**：生卒年、师承、作品编号、首演时间，模型会编得非常像真的。
- **素材版权与肖像权**：人物照片、演奏录音、乐谱影印件，都不能因为"网上搜得到"就用。
- **AI 人像生成**冒充音乐家照片，是不可接受的做法。

所以这件事的正确姿势是：**RAG 约束生成 + 逐条引用 + 无来源即不输出**。

### 5.2 现有 RAG 必须先补真

`teaching-agent.cjs` 的 `retrieve()` 现在是关键词计数，`corpus` 2 条硬编码。要先落 `knowledge/`：

```
knowledge/
  sources/        来源与许可登记（§3.1）
  biographies/    生平材料，Markdown + front-matter 带 sourceId
  songs/          民歌背景、方言、劳动场景、流传地
  strategies/     训练策略依据（已有 2 条，扩展）
```

升级为：分块 → 关键词 + 字符 n-gram 相似度（零依赖可做）→ 返回 `{chunkId, sourceId, text, score}`，生成时把 `sourceId` 注入要求模型输出 `citations[]`：

```json
{"slides":[{"title":"…","points":[
  {"text":"…","citation":"bio-zhang-003#p2"}
]}]}
```

**校验器直接拒绝没有 `citation` 的断言句**。宁可课件短一点，也不能让一句编造的生平混进去。

### 5.3 课件（一期，可靠）

从 `slides[]` JSON 直接渲染 16:9 HTML 幻灯片（正好补上项目文档 4.4「课堂大屏」的缺口）：

| 页型 | 内容 |
|---|---|
| 封面 | 人物/作品 + 时代坐标 |
| 时间线 | 生卒、关键节点 |
| 听辨页 | 引用一段**已授权**音频或直接用本项目合成的参考旋律 |
| 作品结构页 | 与 L1 乐谱层联动，音画同步高亮 |
| 互动页 | 「这里你听到了什么」+ 老师引导语 |
| 来源页 | 逐条列出 citation 与许可，不可省略 |

复用现有"任务事件日志"机制：`kind: 'courseware'`，工具链 `build_biography → verify_citations → render_slides`。

### 5.4 教学视频：分三档承诺，别一次性吹满

| 档 | 做法 | 依赖 | 建议 |

## 6. 我的补充建议（按性价比排序）

**1）先拆地基，否则上面三件事全部做不了。**
`lesson-core.js:validate()` 里的 `4/4`、`8 拍`、`11 音`、`2 小节`、时值枚举，必须改成从 `lesson.teaching` 派生的校验。这一步不产出任何可见功能，但它是所有后续工作的前提，**必须第一个做**。

**2）版权闸门写成硬校验，而不是写在文档里。**
`permittedUse.redistribute !== true` → 直接抛错，课程生成失败。工程纪律比人的自觉更可靠。

**3）"音乐家生平"建议扩成"音乐与土地"，可能比你想的更有价值。**
项目叫「声入山野」，特色线是乡土音乐。对乡村孩子来说，**"这首歌从哪来"比"贝多芬是哪国人"更有共鸣**：一首民歌的来源地、方言发音、劳动场景、谁在唱、什么时候唱。

建议把模块设计成通用的「音乐背景」：既能装贝多芬，也能装《茉莉花》在江苏/河北的两种变体对比。数据模型完全一样，但**产品辨识度和乡村适配度会高一个量级**。

**4）歌词-音符对齐之后，音准偏差可以按"字"报，而不是按"第 3 个音"。**
现在 `coaching.cjs` 报的是音符序号（`index: 3 · 1/2`）。对齐歌词后可以变成「"丽"字偏低 42 音分」——对非音乐专业的老师，这是完全不同的可操作性。这几乎是免费的收益。

**5）一字多音要单独做一个训练点。**
中国民歌「一字多音 / 多字一音」极其常见，而这正是小学模唱最容易糊的地方。`melisma` 字段标记出来后，可以直接生成"拖腔练习"这一新训练策略，补进 `coaching.cjs` 的策略表。

**6）导入必须可逆导出**（§4.6）。这是采纳问题，不是技术问题。

**7）给"教材导入"设一个 5 分钟原则。**
老师从粘贴一首简谱到拿到可上课的课程，**必须 ≤5 分钟**，且中间只需要确认一次（校对界面）。超过这个时长，功能再好也不会被用。

**8）Schema 已存在，要做的是扩展而不是新建。**（更正本报告初稿的一处错误判断）

`public/lessons/lesson.schema.json` **是存在的**（`$id: urn:shengru:lesson:v1`），`molihua.lesson.json` 的 `"$schema": "./lesson.schema.json"` 引用也正确。它是 v2 改造的良好起点，但有两处必须改：

| 现存约束 | 问题 | v2 改法 |
|---|---|---|
| `source` 的 required 含 `pdfPage`（整数，≥1） | 只适用于"PDF 谱例"这一种来源。公有领域曲目、MusicXML 导入、教师手录都没有 PDF 页码 | 加 `sourceType` 判别字段，`pdfPage` 降为仅 `sourceType==='pdf-excerpt'` 时必填 |
| `events` 的 required 含 `degree/octave/pitch/midi/durationBeats` | **没有歌词字段** | 增加可选 `lyric: {lineId, index, syllable, melisma}`；同时新增顶层 `lyrics` 段 |

详见 `docs/开源音乐资源核查报告.md` 第六节。

| 第三方简谱站（简谱之家、爱弹琴、琴谱123、tanqin123） | 均为「免费下载但未标许可」，只能 link-only；且**各家版本互相矛盾** |

### 8.1 素材来源的关键修正

原方案假设"P1 之后第一首新增歌曲选公有领域民歌"。核查后有更优解：

**首选新增曲目改为《小兔子乖乖》**（黎锦晖 1920 年创作，原名《老虎叫门》）。理由：
- 黎锦晖 1967-02-15 逝世 → 保护期 2017-12-31 届满 → **词曲均已在公有领域**，且是他一人作词组曲，无合作作者问题
- 它是**唯一**同时满足「中文 + 儿歌 + 词曲全 PD + 家喻户晓 + 结构极简」的曲目
- 采用 **2/4 拍**，能一次性暴露"现有代码只支持 4/4"的问题

**版权闸门必须机器化执行**（新增依据）：《卖报歌》曲作者聂耳 1935 年逝世（已 PD），但词作者安娥 1976-08-18 逝世 → 词的权利要到 **2026-12-31** 才届满。这种"词曲保护期相差 41 年"的情形，人工审查必然出错。

| `POST` | `/api/lesson/import-jianpu` | 免登录 | 请求 `{text, id?, title?, sourceId?, description?}`；返回解析结果、`difficulty`、`plan`（7 环节）、`licensing`（歌词／曲调各一份闸门裁决）、`steps[]`、`audio.variants[]` |
| `GET` | `/api/lesson/imports/:contentKey/:kind.wav` | 免登录 | `kind ∈ {reference, slow, countIn}`；`contentKey` 是内容哈希（32 位十六进制），同一份谱子重复导入不重复合成 |

- 谱面错误：`400` + `{error, line, column, raw, steps[]}`，能定位到具体行列。
- 版权闸门：`teachingReady:false` 时**不排课、也不合成音频**（`plan` 与 `audio` 均为 `null`）——避免把不可收录的内容做成可分发文件。
- 写操作要求 `Content-Type: application/json` 与 `X-Shengru-Client: local-web`（全局跨站写保护，见 `auth-server.cjs`）。

### 9.2 音乐家生平 → 课件／视频（§5）

| 方法 | 路径 | 登录 | 说明 |
|---|---|---|---|
| `GET` | `/api/courseware` | 免登录 | 可选材料清单：`biographies[]`（含 `facts`／`activities` 计数与 `verified`）、`lessons[]`、`ffmpeg` 探测结果 |
| `POST` | `/api/courseware/build` | 免登录 | 请求 `{bioIds[], lessonId?, theme?, teacher?, school?, asOf?}`；返回完整课件 + `id` + `urls`，并落盘 `.local-data/courseware/<id>.json` |
| `GET` | `/api/courseware/:id` | 免登录 | `:id` 为 24 位十六进制；`format` 取值见下表，缺省返回课件 JSON |

`format` 取值：

| `format` | `Content-Type` | 返回 |
|---|---|---|
| `view` | `text/html` | 独立大屏课件页：可全屏翻页、带打印样式，也可整页下载带走、离线用 |
| *（缺省）* `json` | `application/json` | 课件对象：`slides[]`、`citations[]`、`dropped[]`、`pendingReview`、`stats` |
| `storyboard` | `application/json` | 分镜脚本：`shots[]`（画面／旁白／屏幕文字／时长）、`totalSeconds` |
| `md` | `text/markdown` + `Content-Disposition: attachment` | 分镜脚本 Markdown，可直接打印或贴进教案 |
| `video` | `application/json` | `{ffmpeg, totalSeconds, shots, script:{fps, slidesConcat, pngCommand, ffmpegCommand}}`——**是合成方案，不是 MP4** |
| `svg&n=<序号>` | `image/svg+xml` | 第 `n` 张幻灯片的 1920×1080 矢量图；`n` 会被夹到 `[1, slides.length]` |

`build` 响应中与"可信度"有关的字段（前端直接展示，不藏）：

| 字段 | 含义 |
|---|---|
| `pendingReview` / `pendingReasons[]` | 材料或来源未标 `verifiedBy` 时为 `true`，并逐条说明是谁没核对 |
| `dropped[]` | 被「无来源即不输出」丢掉的句子／整张幻灯片及原因。`dropped` 是**可信度的正面证据**，不是错误 |
| `citations[]` | 本次实际用到的来源元数据（标题、许可、tier、定位、`verifiedBy`） |
| `stats` | `slides`／`bullets`／`citations`／`dropped`／`activityMinutes`／`estimatedMinutes`／`unrelatedChunks` |
| `urls` | 上面全部出口的现成链接，前端不再自己拼 |

### 9.3 为什么这两组接口免登录

它们都不碰教师账号数据：
- 只读**仓库内已登记**的公开材料（`knowledge/`、`public/lessons/`）；
- 导入音频按**内容哈希**寻址缓存（只保留最近 12 份），课件缓存也按内容哈希命名，均不含用户标识。

因此老师可以先「手抄一首谱、生成一份课件」试一遍，再决定要不要注册账号——**先让它可用，再谈留痕**。反之，一切与账号、录音、报告相关的路由仍在 `if(!user) return json(res,401,…)` 之后。
