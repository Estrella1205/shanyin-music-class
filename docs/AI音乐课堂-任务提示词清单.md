## 第一部分 · 方案总览

### 1.1 一句话产品定义

> 一个**教师单机使用**的一站式音乐备课与上课工具：老师输入歌名 + 人数 + 教学条件 → 系统一站式产出课堂流程、课件、逐句教学音频 → 归入「我的备课」→ 上课时一键进入直接教 → 课后自动汇总总结。

### 1.4 现状能力基线（**不要覆盖这些已正确的实现**）

- **音频**：`server/song-render.cjs` → 每首 5 个 WAV：`accompaniment` / `full` / `slow` / `preview` / `accompanimentCountIn`；`server/audio-render.cjs` 共振峰合成。
- **教案**：`server/song-library.cjs` → `buildLessonPlan()` 生成 6 环节（导入/背景/逐句/范唱预备拍/评分纠正/趣味收尾），确定性推导、带 `basis`。
- **乐理**：`server/theory.cjs` → `THEORY`（20 条）、`detectTheory()`、`buildTips()`、`buildBreaks()`。
- **评分**：`server/song-scoring.cjs` → 16kHz 单声道、自相关基频、35 音分阈值、八度等价、无效录音不评分。
- **上传拆解**：`server/audio-decompose.cjs` → `decompose()` / `applyLyrics()`；小花进度条 `public/grow-progress.js`。
- **游戏化**：逐字卡拉OK、星星/连击/徽章、SVG 小鸟飞走 `flyBird()`。
- **课件内核**：`server/courseware.cjs` → `buildCourseware()` / `renderSlidesHtml()` / `buildPptx()` / `renderVideo()`（**已有但没接进课堂前台**）。
- **路由**：`public/app.js` 的 `render()`：`{home,classroom,listen,studio,reports,report,classes,sounds}`；导航在 `public/workspace.js` / `app.js`。
- **免登录**：静默固定本机账号 `currentUser`，账号区显示「本机使用 · 免登录」。
- **测试护栏**：`npm test`（154/154）、`node scripts/verify-studio.cjs`（40/40）、`--file` 模式（40/40）。

下面是所有任务的"宪法"。为节省篇幅，后文每个提示词用 `【读 G1–G8】` 代指；**实际复制给 AI 时，请把本段全文粘贴在提示词最前面一次，再粘贴任务正文**。

```
【全局约束 G1–G8 — 所有任务必须遵守】
G1 本地零依赖：不引入 npm 三方包、不联网运行时依赖、不部署、不推送；改完双击 public/index.html（file://）与 npm start（http://127.0.0.1:4173）两种模式都要可用。
G2 保持原站 UI：沿用原站米色(--cream)＋墨绿(--green)、header/footer/page/panel/btn/chip 组件；所有新 CSS 选择器限定在新容器的作用域内，不覆盖主站全局样式；不加浮动按钮、不加深色星空页。
G3 免登录：不新增任何注册/登录/账号拦截；沿用静默固定本机账号 currentUser。
G4 准确性优先（不可削弱）：
   - 谱面严格校验，不静默修正；不编造未核对的谱面（45 首资料级曲目不得产出逐音教学内容）。
   - 教学结论由谱面/规则确定性推导，可追溯到音符索引；不引用未经核实的教研结论、教材页码。
   - 音准：16kHz 单声道清唱、自相关基频、35 音分阈值、八度等价；无效录音（静音/噪声/多人/带伴奏/音段数不符）不评分只给重录建议。
   - 分数是声学吻合度，不是声乐水平评价；不对学生做生理/心理归因。
   - 范唱是电子合成，不伪装成真人录音。
G5 过程趣味化：任何"处理中/拆解中"状态一律用 public/grow-progress.js 的小花生长进度条呈现，进度只反映服务端真实完成的阶段，不虚报；不出现步骤日志、JSON、代码、工具名。
G6 界面话术铁律（真实上课不该出现的一律不出现）：
   禁止出现在任何页面的可见文本/注释/alt/title/aria 中：
   - "谱面待补"、"请先上传音频完成自动拆解"、"并由老师核对后"、"needs-review"、"status"、"score-ready"、"reference-only"；
   - "Agent"、"任务ID"、"模型"、"配置"、"来源ID"、"谱源"、"链接"、"免责声明"、"未经教师审定"；
   - "观察证据"、"执行工具"、"细节"、"JSON"、"错误码"、"需登录"、"npm"、"API"、"接口"、"字段"、"参数"。
   替代为老师/小朋友视角的话术，例如：
   - 旧"谱面待补：请先上传音频完成自动拆解，并由老师核对后，再使用本环节。" → 新"这首歌还没准备好逐句跟唱，先听一听，或上传一段 demo 让小花帮你整理～"
   - 旧"needs-review 的背景条目" → 新"这条小知识有不同说法，讲的时候当小故事就好啦"
   - 旧错误码 → 新"这次没排好，再试一次就好啦～"
G7 复用优先：先复用上述"现状能力基线"里的函数与数据；新增能力用新文件/新函数，不改写已通过测试的算法。
G8 验收必跑：npm test 全绿 + node scripts/verify-studio.cjs（含 --file）全绿 + 真实浏览器截图目视核对（米色＋墨绿、无深色区域、无 G6 禁词）。改了曲库/算法要 npm run build:library 与 npm run build:vendor。
```
